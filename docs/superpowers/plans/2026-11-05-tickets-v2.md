# Inbox dispatcher tickets v2 TypeScript Implementation Plan

> **Execution:** Use `executing-plans`, test-first, task by task. Plan approved, then stack explicitly amended by Antonio: all TypeScript, including watchers; Next.js, Tailwind and shadcn UI. No Python runtime or Python subprocess wrappers. The stack decision is settled. Behavioral deviations still need approval.

**Goal:** Read incoming messages into proposed tickets, start normal OpenChamber chats only after approval on a local Next.js page, and recover through durable SQLite jobs.

**Architecture:** One manually started Node daemon owns SQLite, the job runner, TypeScript watcher subprocesses and a custom HTTP server handing requests to Next.js. Route handlers only read state or commit local actions/jobs. Windows COM, DPAPI and read-only file snapshots use Node native libraries, not Python bridges.

**Tech Stack:** Node 26.4.0, TypeScript, Next.js App Router, React, Tailwind CSS, shadcn/ui, `node:sqlite`, Vitest and React Testing Library. Native Windows adapters use `koffi` and `winax`, subject to Phase 0 proof. No workflow platform, ORM, separate web service or cloud deployment.

export function retryDelay(n: number, initial: number, cap: number, jitter: number, random: number, floor: number): number {
  const base = Math.min(cap, initial * 2 ** Math.min(Math.max(0, n - 1), 30));
  return Math.max(Math.max(0, floor), Math.min(cap, base * (1 - jitter + 2 * jitter * random)));
